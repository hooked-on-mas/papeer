# Papeer PC・Web共通化 計画書（v2）

更新日: 2026-11-22。旧計画書群（`shared-app-plan.md` ほか）は `docs/archive/shared-app-v1/` に保管し、**参照のみ**とする。作業の正本はこの文書。進め方のルールは [AGENTS.md](../AGENTS.md)、日々の記録は [worklog.md](worklog.md)。

## 1. 目的と完成の判断基準

**目的:** 利用者本人が、iPad（Web版）とPC（Native版）で同じPapeerを普段使いできる状態にする。

想定する使い方:
- 移動中にiPadのブラウザで論文PDFを読み、ペン・付箋・ノート・Markdownで書き込む（オフラインもあり得る）
- 後でオフィスのPCで同じ内容を開き、続きを読んだり書き足したりする
- 1人で使う。PCとWebで**同時に編集することはない**

**完成の判断基準:** 下記M1〜M4を終えた版を、利用者が実機で**1週間ほど普段使い**して、困る問題がなければ完成。

やらないこと（今回の範囲外）:
- 同時編集・逆順受信・応答消失中の操作など、極端な同期障害への対応（実装済みのコードは残すが、検証を増やさない）
- アプリに組み込む移行機能（移行は一時スクリプトで行う）
- 試用版配布ツール（`tools/trial/`）による隔離インストール
- 公開・複数アカウント対応（§5 今後の計画へ）

### M1.5. 普段使いできる GUI の復元（元の Papeer 風）
元の Papeer のレイアウト・アイコン・メニュー構造へ戻し、PC と iPad で普段使いして違和感がないレベルにする（完璧な一致や細部演出までは追わない）。旧 store／API に密結合した `LibrarySidebar.tsx`・`InkToolbar.tsx`・`ReaderToolbar.tsx` は直接 import せず、sidecar 非依存の `WorkspaceChrome.tsx`・`LibraryRows.tsx`・`components/ui/*`・`index.css` を再利用して共通セッション側へ被せる。
- [x] **全体レイアウトと起動画面**: `LibraryContentConnection` の上部縦積みカタログを廃止し、`WorkspaceChrome` による左リサイズ可能サイドバー＋折りたたみレール＋ヘッダーへ移行（iPad・狭幅では開閉オーバーレイ）。`WorkspacePreferences` の `一覧の最大高さ` はサイドバー幅等へ整理。`BootstrapConnection` の起動画面を整え、初回に不要な「端末のパスフレーズ（`ProviderOfflinePanel`）」は M3 でオフライン利用を有効化するまで隠す
- [x] **資料一覧（サイドバー内）**: `LibraryCatalogPanel` の素のボタン羅列をやめ、`LibraryRows` を使ったアイコン付きツリー＋検索バー＋新規作成／PDF取込アイコン＋行メニュー（複数選択時のみ一括操作バー表示）へ整理
- [x] **リーダー・書き込み・Markdown・付属パネル・設定**: `DocumentWritingToolbar` を元の Papeer に近いコンパクトなリーダーバー＋アイコン付き書き込みバーへ再構成（色・太さ・消しゴム設定・選択操作は該当ツール／選択中のみ展開、ロック・非表示・詳細操作は `…` メニューへ）。`CanonicalMarkdownToolbar`・`RelatedContentPanel`・`WorkspaceSettings` ダイアログも `components/ui/*` で整形
- [x] **主要 E2E テストの追従と見た目確認**: 日常操作の主要 E2E テストだけ新 UI に合わせて更新し、仮画面レイアウト前提の細かい旧 E2E テスト（上部カタログ高さ等）は整理・削減する。完了前に開発サーバーで実画面（PC 幅・iPad 幅）を目視またはスクリーンショットで確認する
- **実機確認①:** 開発モードのWeb（PC・iPad）とPC版で、見た目・操作感を含め書き込み・ノート・Markdown・Libraryの日常操作
