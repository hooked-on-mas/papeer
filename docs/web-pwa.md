# Web版のインストールと更新

公開先は https://hooked-on-mas.github.io/papeer/ 。サーバーの追加は不要で、GitHub PagesとGoogle Drive APIを使う。

## インストール

- iPad・iPhone：Safariで開き、共有メニューの「ホーム画面に追加」を選ぶ。「Webアプリとして開く」があればオンにする。
- PC・Android：画面下の「アプリとして使う」を開く。対応ブラウザーでインストールボタンが出る。出ない場合はブラウザーのメニューからインストールする。

インストール後も閲覧・書き込み・Drive同期はブラウザー版と同じ。Googleログインは起動後に行い、アクセストークンを端末に永続保存しない。通常のSafariタブとホーム画面アプリでは保存領域が分かれる場合があるため、それぞれでログインする。Webからの翻訳やAI設定は提供しない。

## iPhoneの表示と操作

スマホでは日本語訳のPDFがあれば自動で開き、訳文がなければ原文を開く。直前に表示していたファイルがあれば、その読書位置を優先する。「資料」のファイル選択欄・タイトル行・タブ・フッター・書き込みツールを本文の上に積み重ねず、通常の閲覧は上部の操作バー1段で始まる。ライブラリ、ページ移動、日本語訳と原文の切替、読書メニューを並べる。日本語訳・原文とも同じ広さで表示し、集中表示を選び直す必要はない。

読書メニューから倍率・対訳表示・PDFの保存・メモ・チャット・付箋・添付ファイル・Google接続を開く。「書き込みを開始」でツールを出し、終了すると追記を残したまま広い閲覧に戻る。色・太さ・「指でも書く」、取り消し・やり直し・同期は書き込み設定にまとめる。既定では指はスクロール用。通常の閲覧では指のスクロールやピンチをブラウザーに任せる。対訳を2つ表示するときは上下に並べる。横向きでもこの配置を維持する。オフライン・更新などの通知は短く表示し、開くと詳細を確認できる。入力欄は標準で16px相当とし、主要ボタンは44pxの領域を確保する。[Appleの操作領域の指針](https://developer.apple.com/design/tips/)も参照。

幅375px以上では操作バーの虫眼鏡で150%への拡大と幅合わせを切り替える。より狭い画面では読書メニューの倍率を使う。2段組などの小さい本文は、幅合わせだけで読みやすいとは限らない。拡大時はPDF内を横に動かして読む。PDFの本文・配置は変更しない。接続操作はメニュー内で「Google接続」と明記し、保存ライブラリの見出しと選択欄は上下に並べる。色設定は44pxの色見本からネイティブの入力を開く。

## オフラインの範囲

初回オンライン起動後、アプリ本体をオフラインで開ける。PDF・ノートの一覧や本文はDriveから取得するため、閉じてからオフラインで資料を開き直す機能は提供しない。Googleログイン、資料の追加取得、Driveへの送信には通信が必要。

すでに開いているPDFへの未送信の追記は、ブラウザー内に保存して再送する。再起動後はオンラインで同じライブラリにログインして再送する。文字メモは入力中から端末に下書きを保存し、配置を確定するとDriveへの追記になる。下書きはライブラリ・PDFの版・ページで分ける。保存容量不足時は入力や描いた線をメモリーに残し、再保存できるまで画面内のページ移動・資料変更を止める。閉じる際にもブラウザーへ警告を要求するが、OSの強制終了やサイトデータ削除には耐えない。画面に保存エラーがあるときは、閉じる前に再保存またはコピーする。

Service Workerが保存するのは、ビルド時に列挙した公開HTML・JavaScript・CSS・フォント・アイコン・manifestだけ。Googleログイン、Drive API、PDF、ライブラリ情報、アクセストークンはキャッシュしない。汎用的なruntime cacheやAPIへの代替応答は作らない。既存の追記下書きはService Workerのキャッシュとは別で、更新時に削除しない。

## 更新

新しいアプリ本体がダウンロードできると更新案内と「更新を適用」を表示する。端末に保存できていない書き込みがある間や、別のPapeerのタブ・ホーム画面アプリが開いている間は切り替えない。更新操作をした画面だけを再読み込みし、端末に保存した下書きは維持する。更新ボタンのない旧版では、Papeerのタブとホーム画面アプリをすべて閉じ、開き直す。読書中の自動切替は行わない。古い本体のキャッシュは、新しいWorkerの有効化時に同じ公開パスの分だけ削除する。端末の空き容量や通信の問題で準備できない場合は案内を表示し、再接続・画面に戻ったときにも再試行する。

`frontend/webPwa.ts`はWebビルド限定のViteプラグイン。manifestのid/start_url/scopeとアイコン、Worker URLは相対パスで、`/papeer/`にも対応する。内容ハッシュでキャッシュを更新する。PCのTauriビルドではWorkerを出力・登録しない。外部ライブラリやサーバーは追加しない。

## 検証

`frontend`で`pnpm build:web`後に`node --test e2e/webPwa.browser.test.ts`。Edgeの隔離した一時プロファイルで、`/papeer/`配信、インストール条件、アイコン取得、HTTPキャッシュ無効時のオフライン起動、公開資産のみのキャッシュ、複数タブをまたぐ更新待機、下書き保持を検証する。実公開先の検証には`PAPEER_PWA_TEST_URL=https://hooked-on-mas.github.io/papeer/`を設定する。Google認証・Driveの試験リクエストにはダミー応答を使う。

iPad用のmanifest、Apple touch icon、safe areaと案内を実装し、iPad相当の画面サイズも確認する。iPad実機への追加操作とSafariのGoogle認証は実機確認が別途必要。

iPhone向けは `node --test e2e/webIphone.browser.test.ts` でWebKitとEdgeを使い、幅320・375・390・430px、横向き、PDFの幅・ページ操作・倍率・集中表示・文字メモ保存・対訳の上下表示・接続メニューを確認する。Google・Driveは合成応答を使用する。通信モックがWorkerに迂回されないよう閲覧試験ではWorkerを無効化し、PWA自体は別の試験で確認する（[Playwrightの注意事項](https://playwright.dev/docs/network#missing-network-events-and-service-workers)）。EdgeではCDPのタッチ入力で指スクロールと描画の分離も確認する。ホーム画面アプリの判定とキーボード表示後に相当する高さの縮小も模擬するが、実際のiOSキーボード・ノッチ・Safariの認証・ホーム画面への追加を実機検証したものではない。

参考：[Appleのホーム画面追加手順](https://support.apple.com/ja-jp/guide/ipad/ipad8f1f7a29/ipados)、[Service Workerの更新と待機](https://web.dev/learn/pwa/update)。
