# 段・ページをまたぐ翻訳

本文の翻訳単位と、PDF上の配置領域を分離する。結合した文は一度だけ翻訳し、訳文を複数の元領域に配分する。論文名、著者名、出版社、ファイル名、特定ページ番号による分岐は使わない。

## 処理

1. 元PDFからブロックと数式を抽出する。繰り返しヘッダー、ページ番号、小さな脚注などを主本文の流れから除外する。これらのブロック自体は削除しない。
2. 本文の横位置と幅から段間の空白を推定する。2段の場合は左段→右段の順にし、段を横断する見出し・図表などで領域を区切る。1段に各1個の長い段落しかない場合も、十分な文章量と縦方向の重なりがあれば認識する。明確な3段構成は自動結合の対象外とする。
3. 段境界または連続ページの境界で、前の本文が終止記号で終わらず、次の本文が継続を示す始まり方の場合に結合する。見出し、独立数式、表、図、参考文献などを結合の障壁とする。結合後の原文が6,000文字を超える場合も見送る。
4. 仮想ブロックに元のブロックID・配置ページ・数式の出典ページを保持し、通常の翻訳検証・再試行処理へ渡す。
5. 日本語の句読点などを候補に、元領域の面積に応じて訳文を配分する。数式トークンは分割しない。連結した配分結果が翻訳全文と完全に一致し、数式の数も一致することを検査する。安全な区切りがない短文は丸ごと一方に置くため、もう一方が空になる場合がある。
6. 移動した数式は、その数式が元々載っていたページから画像を取得する。

`document.json` の `continuations` に結合グループ、`continuation_decisions` に境界ごとの判断理由、各ページの `reading_order` に段構成を保存する。

## ページ指定・再開・反映

選択ページが結合グループの一部なら、関連ページを追加する。この処理を繰り返すため、隣接する別の継続文が連なる場合には複数ページまで広がる。UIの説明と進捗に表示し、`requested_pages` と `selected_pages` をレポートに記録する。

ページごとに同じ結合文を再送信しない。キャッシュと再試行回数は翻訳単位ごとに保持する。配置先の一部が失敗した場合、完了処理では関連ページ全体を未完成扱いに戻し、共通文の片側だけを残さない。

新規検証ツールも同じ依存関係を使う。`apply_layout_review` は結合文を共有するページの部分反映と、ページごとに異なる共通訳文を拒否する。PDFとMarkdownの配分方法は共通で、変更前のライブラリ出力はバックアップされる。

## 検証と限界

`python -m tools.study_reading_flow --papers <papers> --output <新しいフォルダー> --count 10 --seed 20260920` で、論文全体の境界候補を調べ、種別ごとに固定シードでサンプリングする。候補がない論文は通常ページを選ぶ。すべて原文から再抽出・新規翻訳し、保存済み訳文を評価に使わない。

`tools.audit_flow_review` は数式トークン、配分前後の全文一致、原文ハッシュ、ページ間の訳文一致を検査し、PDFiumでも描画する。画像の読書順、意味の連続性、重なりは別途目視確認する。

これは確定的な言語構文解析ではなく、幾何と文字列による保守的な推定である。図表を挟んだ継続、短すぎる断片、複雑な混在構成、OCRが必要なPDFなどは取りこぼす。図中ラベル、数式と本文の抽出時の混在、語彙の統一はこの処理だけでは解決しない。10本での検証は一般精度を保証する独立ベンチマークではない。
