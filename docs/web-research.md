# Web検索と参考文献の取り込み

訳語の用例調査は「訳語の修正」から利用できます。学術・公的な日本語原文の出典と短い引用を表示し、機械翻訳の訳語を根拠には使いません。調査結果だけでは訳文・辞書を変更しません。詳しくは [翻訳仕様の「読書中の訳語修正とWeb調査」](translation.md#読書中の訳語修正とweb調査) を参照してください。

## チャットで調べる

入力欄の「Web検索 ON/OFF」で、次の質問でWebを検索するかを選びます。既定はOFFです。論文ごとの選択を保存し、アプリを開き直しても引き継ぎます。本文の参照範囲（この論文・選んだ論文・フォルダー内）とは独立しています。

- OFF：指定した論文の本文と、明示的に添付した調査結果で回答します。
- ON：本文に加えてWebを検索し、本文のページ引用とWebの出典リンクを分けて表示します。

検索状態と出典は質問・回答に保存します。現在のスイッチをOFFにしても、過去の回答の「Web検索あり」や出典は変わりません。検索で見つかった関連文献は、回答中の文献カードを開くと概要・入手先・PDFを確認できます。

Web検索はCodex CLI・Claude Code CLI・Antigravity CLIに対応しています。設定のAI接続を切り替えても、同じスイッチ・参考文献の詳細画面・PDF取り込みを使えます。API／ローカルモデルの接続はWeb検索に未対応で、検索スイッチは使えません。通常の翻訳・サマリー作成はWeb検索を有効にしません。Web検索の出典を確認できないときは、その質問を成功した回答として履歴に保存しません。

Claude Codeでは検索時だけ `WebSearch`・`WebFetch` を有効にします。組織のポリシーなどで検索が利用できない場合は、出典なしの回答を調査結果として保存しません。Antigravityでは実行ごとに一時フォルダーへ専用エージェントを作り、検索時は `search_web`・`read_url_content`、検索しないときは回答の終了処理だけを使用可能にします。検索時の自動承認はこの構成内に限定され、コマンド実行・ファイル操作・MCP・別エージェントの呼び出しは公開しません。ユーザーの設定ファイルは変更しません。

Antigravityの調査結果は、プロンプトにJSONスキーマを含め、アプリ側で必須項目・型を検証してから読み取ります。agy 1.3.1では専用エージェントと `--json-schema` の組み合わせで空の関数呼び出しエラーが再現したため、このCLIオプションは使用しません。不正なJSONやツール呼び出しは回答形式のエラーとして扱い、接続エラーとして同じ要求を自動再送しません。

実装の根拠：[Claude Codeのツール](https://code.claude.com/docs/en/tools-reference)、[Antigravityのエージェント構成](https://www.antigravity.google/docs/subagents/)、[AntigravityのWebツール](https://www.antigravity.google/docs/sdk/tools/)、[Antigravityの構造化出力](https://antigravity.google/docs/cli/headless/)。CLIが古い場合は更新してください。

## 参考文献の内容と入手先

「論文マップ」タブ（Ctrl+6）の一覧や関係図から文献を選ぶと詳細を表示します。幅900px以上では一覧の下に詳細を残し、狭い画面では「一覧に戻る」で検索条件とスクロール位置を引き継ぎます。「内容・入手先を取得」で、指定した文献の概要、確認した出典、直接取得できる公開PDFを調べます。

詳細は著者・掲載誌、PDFの操作、論文の概要を中心に表示します。抄録の原文、出典、取り込み設定、取得状況は必要なときに開けます。取得できなかった理由と候補URLは「取得状況・詳細」に保存し、概要には混ぜません。以前の取得結果も表示時にこの形式へ整理します。詳細には独立したスクロール領域があり、長い抄録でも最後まで読めます。

ネットワークは狭いパネルでも初期表示します。ノードをドラッグすると位置を変えられ、背景のドラッグで画面を移動、ホイールと＋／−で拡大縮小できます。「全体を表示」で配置と倍率を戻します。文献へのカーソル移動と選択でつながりを強調し、引用の向きを静止した矢印で示します。図の表示件数・表示する論文・登録状態をそれぞれ変更できます。

### 設定と取得の順番

文献ごとの概要・入手先の補完には設定の「論文情報の取得にAIを使う」（既定はOFF）と「情報取得の接続先」を共通で使います。ONにすると、表示中の論文の未取得の参考文献を最大5件同時に処理し、1件終わるたびに次を補充します。OFFではこの補完を開始せず、実行中の補完も中止します。マップの外部探索は別の「論文マップで外部の関連論文を自動取得する」（既定はON）で制御します。確認用のDOI・arXiv・Google ScholarリンクはOFFでも開けます。

1. Semantic ScholarのAcademic Graph APIで、DOI・arXiv ID、またはタイトルから検索します。
2. 見つからない、利用制限・接続エラーがある、項目が不足する場合はCrossref REST APIで補完します。Semantic Scholarで取得できた値は保持します。
3. 書誌サービスとPDFの実取得確認後も情報が不足する場合だけ、設定の情報取得AIによるWeb検索で補います。確認済みの書誌情報と不足項目を渡し、識別子やタイトルが違う補完結果は採用しません。LLM補完に失敗しても書誌サービスの結果は保存します。

取得する情報はタイトル、筆頭著者、出版年、掲載誌、DOI・arXiv ID、抄録、出典、公開PDFの候補です。詳細に書誌情報と取得した抄録（原文）、取得元のリンクを表示します。APIだけで必要な情報とPDFが揃えばLLMの利用枠・トークンは消費しません。API／ローカルモデルの接続でも書誌サービスから取得できますが、Web検索ができない接続先では外部情報のLLM補完は使えず、未確認の情報を明記します。

タイトル検索では強いタイトル一致、出版年と筆頭著者を確認し、複数の識別子が残る場合は特定済みと扱いません。既に確認した識別子があれば再取得でも使います。以前のLLMだけの取得結果は、この取得方法で一度再確認します。書誌APIへのリクエスト間隔は同じ接続先の全処理で共有し、利用制限中は同じサービスに続けて送らず別の取得元へ進みます。成功したAPI応答は最大15分、256件までメモリに保持します。

参考文献パネルを表示している間に次の未取得文献を補充し、別の画面では実行中の取得が終わったところで待機します。接続が途切れた場合は待機し、結果を全く取得できないエラーでは一時停止して「収集を再開」を表示します。PDFの追加と本文サマリーの作成は、それぞれのボタンで実行します。PDF候補は実際のダウンロードと冒頭のタイトル・DOIの一致を確認し、404・別資料のPDFは除外して理由とURLを表示します。

参考文献の収集中も、同じ論文のサマリー作成・チャット・翻訳・訳語の確認・PDF書き出しを利用できます。先にこれらの処理を開始した場合も、収集は並行して進みます。収集の同時5件上限は別に数えます。PDFのOCR・参考文献PDFの取り込み・論文の削除・バックアップ・復元・同期は、競合を避けるため収集の終了を待ちます。

APIの根拠：[Semantic Scholar Academic Graph API](https://api.semanticscholar.org/api-docs/graph)、[Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)、[Crossrefの全文リンク](https://www.crossref.org/documentation/retrieve-metadata/text-and-data-mining/)。

### 論文マップの候補と関係図

[Connected Papersの研究探索](https://www.connectedpapers.com/about)を参考に、周辺の論文・直接の参考文献・この論文を引用・近い論文・先行研究・後続研究を一つの表示切り替えにまとめています。「すべて／登録済み／未登録」とタイトル・著者・DOI検索は、どの表示にも共通です。

直接の参考文献は、読んでいる論文のDOIからSemantic Scholarの一覧を取得し、Crossrefの参考文献情報で補います。DOIがないarXiv論文はarXiv IDでSemantic Scholarに問い合わせます（arXivのDOIもarXiv IDで照合し、Crossrefへの不要な照会を省きます）。APIが成功してもPDFの参考文献欄を毎回照合し、APIにない文献、PDF内の文献番号・掲載ページを残します。著者・年・識別子がなくPDFでも確認できない説明文などの候補は除外し、件数を取得状況に表示します。PDFの参考文献がある場合、Semantic Scholarだけが挙げてPDF・Crossrefと照合できない文献は保持しつつ「未確認の参考文献候補」として区別し、直接引用の実線や引用数に加えません。各文献の詳細にはSemantic Scholar・Crossref・PDFの取得元を表示します。取得失敗時は保存済みの情報とPDFを表示します。曖昧なタイトル、出版年や識別子の不一致は自動統合しません。

近い論文は「起点 → 直接の参考文献 → その引用先」をたどり、直接の参考文献の2件以上が共通して引用する文献を優先します。詳細には「直接の参考文献のうち○件が引用」と表示します。共通参考文献・共引用も使い、タイトルと保存済み抄録のTF-IDF／コサイン類似度、Semantic Scholarのテーマ推薦と順位融合します。外部の文献にも語句の比較を適用し、一般的な基礎文献を共有するだけでテーマの近い論文より強く加点しません。タイトルの語句を重視し、直接引用の図への選出やDOIがない文献の照合順にも使います。登録済みであることは関連度に加点しません。

直接引用は最大1000件を取得し、そのうち外部情報を確認できた最大100件の共通引用先を最大500件取得します。Semantic Scholar・Crossref・PDFから得た直接の参考文献もDOIでSemantic Scholarに照合し、引用情報が不足していても探索に含めます。DOIのない文献の外部照合はテーマの近い順に最大20件、テーマ推薦は最大20件です。先行研究は起点・直接の参考文献・近い論文上位20件から成る論文群の2件以上から引用される文献、後続研究はこの論文群の2件以上を引用する文献です。外部の被引用・後続探索は起点を含む最大100論文を対象に、各論文のAPI応答順で最大200件まで取得します。起点を最初に取得し、同じ後続論文が複数の対象を引用する場合は、個々のAPI応答で確認した引用先を統合します。新しい順・被引用数順での網羅的な取得ではありません。参考文献情報に上限・欠落がある場合は取得状況に表示します。結果は取得範囲に基づき、重複引用は一つとして数えます。

実際の引用は「引用する論文 → 引用される文献」の実線、類似・推薦は矢印のない点線です。起点以外の文献同士も引用の実線で結び、確認済みの2段階の引用経路がある候補には起点からの点線を足しません。複数の関係があるときは引用を優先し、詳細に理由をすべて表示します。円の面積は被引用数に対して対数的に増やし、上限を設けます。外部の被引用数を使う図では未取得の論文を最小サイズの白抜きにし、外部の情報がない図ではライブラリ内の数を使います。取得元を混ぜず凡例に示し、起点と選択には別の外周を付けます。図は最大60件、周辺表示では直接引用を優先しつつ近い論文用に最大15件を確保し、その候補につながる参考文献を図に優先して残します。他の表示でも経路をつなぐ参考文献を60件の上限内で、登録状態の絞り込みに従って図だけに追加し、追加件数を凡例に表示します。選択中の文献につながる参考文献を優先します。一覧は取得済み候補をすべて保持し、図にない文献を選ぶと図へ追加します。ホバーは下見だけで通信しません。

一覧は関連順、新しい順、ライブラリ内の被引用順で並べ替えできます。被引用数にはライブラリ内かSemantic Scholar由来かを添えます。「この論文を中心に見る」は未登録論文にも対応し、「戻る」で起点・選択・絞り込み・一覧位置・図の表示位置を復元します。図は引用でつながる文献を近くに集める配置を使います。候補追加時は図の既存配置を保ち、追加文献だけを配置します。「全体を表示」で全体を再配置します。旧方式の保存結果も表示しながら自動更新します。

概要には「抄録に基づく」「公開本文に基づく」「書誌情報のみ」の区別と確認日を表示します。文献を特定できなかったときはその状態を表示し、PDF候補を出しません。参考文献のDOI・arXiv IDや確認済みタイトルと検索結果が食い違う場合、その結果の概要・PDF候補は採用しません。対象文献名、元と検索結果の識別子、検索結果のタイトル・出典、確認日時を失敗の記録として別に保存し、文献の詳細に表示します。既に確認した情報と取り込み済みPDFは保持し、正常に再取得できると失敗表示を解消します。プレプリントと出版版の違いも自動で同一視しません。

照合できなかった文献は「文献の照合を確認してください」から詳細を開けます。タブやアプリを開き直しても同じ文献を自動で再試行せず、ほかの文献の収集は続けます。元の文献リンクと食い違った情報を確認し、「情報を再取得」で再検索できます。通信障害・利用制限など、文献単位の照合失敗と確認できないエラーでは収集を一時停止します。

### グループの表示とAIによる説明

図の初期表示は幅900px以上で30件、それ未満で20件です。「図の表示件数」で20・40・60件に変更でき、一覧にはすべての候補を残します。起点以外の引用関係・共通の引用先・共通の引用元から密につながるグループを分け、色と輪郭で囲みます。図に表示されていない文献の引用情報も分類に使います。起点へのつながりだけではグループにせず、類似・推薦だけの関係も分類には使いません。グループ間と円同士の間隔を取り、「つながりのまとまり」から各グループを拡大できます。

初期配置と「全体を表示」では、デスクトップの横幅を使うよう図の主方向を揃え、グループ全体を移動して輪郭の領域を分離します。グループ名と番号はノード群の横に確保した余白に折り返して表示し、その余白まで色付きの輪郭を広げます。画面上の円の実寸（最小サイズを含む）と名前の領域を検査し、収まらない場合はグループを領域ごと配置し直します。細長く密集した保存配置はグループ内の円も詰め直します。論文タイトルや研究分野ごとの例外は使いません。名前同士・ノード・論文ラベルの重なりを避け、名前の背景に箱は重ねません。図の下にも名前の一覧を残し、AIの説明は「つながりのまとまり」で読めます。ホバーの下見と拡大縮小ボタンは図の下に置きます。デスクトップでは凡例・名前一覧・説明欄の高さを測り、図に必要な高さを確保します。

初回のグループ化とAIによる説明は、外部探索と結果の読み込みが終わってから開始します。取得途中も論文と引用線は表示し、再取得中の分類には前回取得が終わった時点の引用情報を使います。取得に失敗した場合は、取得できた範囲でグループ化します。外部探索がOFFの場合は保存済みの情報で分類します。

取得後にグループ構成や円の大きさが変わって保存配置が重なった場合は、一度配置を修復します。同じ構成での再表示、説明文だけの更新、重なりを起こさない追加取得では座標を維持します。手動で動かした表示範囲やノードは同じ構成では維持し、「全体を表示」で自動配置に戻せます。画面上の配置修復にかかった時間も「表示・配置」の計測に含めます。

近い論文の予約枠は起点・選択を除く図の約3分の1、最大15件です。残りはテーマの近い直接引用と、引用経路をつなぐ参考文献に分けます。グループの色は起点との関連の強さを意味しません。「つながりのまとまり」には、起点の直接引用、起点を引用、参考文献の先の引用、共通参考文献をそれぞれ区別した件数と、共通参考文献の名前を表示します。

「論文情報の取得にAIを使う」がONの場合、外部探索が落ち着いてからグループ名と共通点を生成します。設定の「情報取得の接続先」「情報取得モデル」で解決した接続を使い、翻訳用の設定を直接呼びません。所属論文のタイトル・保存済み抄録・引用関係だけを材料にし、追加のWeb検索はしません。API／ローカルモデルにも対応します。「説明の根拠」で所属論文と使用モデル・生成時間を確認できます。資料がタイトルだけの場合や題材が混在する場合は、その限界も説明するよう依頼します。

説明は起点ごとの専用キャッシュに7日間保存し、所属論文・材料・情報取得モデルが変わった場合は再生成します。期限後も以前の説明を表示しながら更新します。生成待ち・失敗・AI設定OFFでも引用によるグループ表示は残り、説明の追加は配置や倍率を変更しません。「説明を更新／説明を再試行」でやり直せます。タブや起点を離れると生成を中止し、AI設定OFFでも実行中の生成を止めます。説明を参考文献の引用として保存することはありません。

### 構築時間を確認する

重複照合はDOI・arXiv ID・外部IDの索引で一致候補を絞ります。タイトルの正規化を再利用し、タイトル長と類似度の上限から95%の一致に届かない組み合わせを除きます。残った候補には従来と同じ一致判定を適用するため、識別子の矛盾や複数候補を自動統合しない条件は維持します。索引は構築ごとに作り直し、取り込み・書誌情報の編集で古い一致を残しません。取得途中で候補が増えない工程では直前の順位を再利用し、完了時の結果を二重に構築しません。

論文マップ上部の「構築時間の内訳」を開くと、直近の探索の経過時間・工程ごとの時間・回数が表示されます。Semantic Scholar・Crossrefの参考文献取得、PDF参考文献との統合、Semantic Scholarでの起点の特定・参考文献・共通引用先・先行後続研究の取得、登録済みPDFとの照合、語句の類似度計算、結果の保存を計測します。通信と応答受信、取得間隔の待機、同時処理の順番待ち、応答キャッシュの再利用は別の行です。

時間は経過時間で、CPU使用時間ではありません。親工程の時間には下の工程を含むため、行をそのまま足しても全体時間にはなりません。計測値には子工程を除いた時間も保存します。図の追加・再配置の計算時間は、この画面を開いてからの累計として別に表示し、外部探索の時間に含めません。HTMLの描画時間は計測対象外です。

計測結果は起点ごとの探索キャッシュに保存し、途中の取得結果とともに更新します。中止・通信失敗でも最後まで計測し、状態と取得済み結果を残します。過去のキャッシュには計測値がないため、次の取得から表示します。ログには `paper_map_timing` の名前で記録し、通信URLや検索語を計測記録に入れません。

実データの独立した計測には次を使えます。元のライブラリは読み取り専用で開き、データベースと保存済みPDF解析結果を一時フォルダーに複製します。保存済みマップの構築を計測後、その論文の探索キャッシュをコピー側だけで空にして外部取得を測ります。`--timeout` は外部探索の中止要求までの秒数で、通信・構築処理の終了時に中止が反映されます。

```powershell
uv run python tools/profile_paper_map.py --paper-id <論文ID> --report tmp/map-timing.json --timeout 300
```

`--cached-only` は外部取得を行わず、`--map-output tmp/map-data.json` は画面での配置計測用のマップ応答を保存します。配置をブラウザーで測る場合は、`frontend` ディレクトリで `node e2e/profilePaperMap.ts ../tmp/map-data.json ../tmp/map-timing.json` を実行します（Microsoft Edgeが必要）。API通信は固定応答に置き換え、最大60件の配置計算を測ります。開発サーバーの起動時間やHTML描画時間は含めません。

## PDFを取り込む

公開PDFが複数ある場合は、公開元と版（出版版・著者最終稿・プレプリント・未確認）を選びます。保存先は元の論文のフォルダーを既定とし、別のフォルダーも選べます。「取り込み後にサマリーを作成」は任意で、既定はOFFです。

この画面では、Webで見つかった公開PDFを取り込みます。直接取得できる公開PDFがない場合は「Google Scholarで開く」でタイトル検索を開けます。「出典・入手先」から各出典へも移動できます。既に関連付けた論文や同じ内容のPDFは再利用し、既存のサマリーは上書きしません。

PDFは100MBまでです。取得時は転送先も確認し、公開インターネット上のファイルに限ります。ログイン画面などのHTML、空のPDF、パスワード付きPDFは取り込めません。

取り込みが終わっても、表示中の元の論文は切り替えません。文献の詳細に「論文を開く」「サマリーを見る」を表示します。取り込んだPDFには元の参考文献との関連付けを保存し、引用ネットワークに登録済み文献として反映します。

## サマリーと比較

サマリーは取り込んだPDFの本文から作成し、日本語訳の作成は不要です。Webで読んだ抄録の概要とは別に扱います。本文を読み取れないスキャンPDFはOCRを案内し、PDFを保存した状態で残します。

サマリー作成でエラーや中止が起きても、取り込んだPDFと元の文献との関連付けは保持します。「サマリーを作成」で再試行できます。

「元の論文と比較する」は、元の論文と取り込んだ論文をチャットの参照対象に選び、調査結果と質問の下書きを添付します。送信とWeb検索の選択はユーザーが行います。PDF・サマリーを開いた後は「元の論文のマップへ戻る」で、選択・探索範囲・絞り込み・一覧と図の位置を引き継いで戻れます。

## 保存

調査結果と取り込んだ論文の関連付けはライブラリ内のデータベースに保存し、チャットには送信時の出典と調査結果を保存します。既存のバックアップ・復元・フォルダー同期で引き継ぎます。古いライブラリは自動移行し、既存の本文とチャット履歴は保持します。

マップを開くと保存済みの結果をすぐ表示し、外部探索がONなら不足・期限切れの情報を取得します。成功結果は7日間再利用し、期限後も保存済み結果を表示しながら更新します。別タブへ移ると追加取得を止めます。失敗・利用制限でも取得済みの結果を残し、再試行を表示します。探索で見つかっただけの文献を、起点の直接の参考文献として記録しません。[Semantic Scholarの公式API仕様](https://api.semanticscholar.org/api-docs/)に基づいて取得します。

外部探索はSemantic Scholarを使い、OpenAlexへ通信しません。以前のOpenAlexの保存結果は取得元を添えて表示し、更新時にSemantic Scholarへ切り替えます。設定の「Semantic Scholar APIキー」は任意で、入力したキーはアプリの終了時に破棄し、ライブラリやバックアップへ保存しません。起動時には環境変数 `PAPEER_SEMANTIC_SCHOLAR_API_KEY`（または `SEMANTIC_SCHOLAR_API_KEY`）も使えます。Semantic ScholarとCrossrefの取得はサービスごとに直列化し、1.1秒以上の間隔を空けます。429・503の応答では取得を休止し、保存済み結果を残します。
