# HTML 資料

論文や独立ノートに、自分で用意した .html ファイルを「資料」として持たせ、見た目（CSS・埋め込み画像）のまま読めます。サマリーや図解をまとめた HTML を、論文のそばに置いておくための機能です。資料は読むだけで、アプリの中では編集しません。Web 記事の取り込みではなく、アプリ内の AI で資料を作る機能も今はありません。

## 取り込む

- 右パネルの「メモ」「資料」の切り替えで「資料」を選び、「資料を追加」から .html を選びます。
- 論文行・独立ノート行、メモ欄、資料欄へのドロップでも取り込めます（複数可）。.md と .html を一緒にドロップすると、それぞれメモと資料になります。PDF などほかの種類が混ざったドロップは取り込みません。
- UTF-8 で保存した .html だけを扱います（先頭の BOM は無視します）。本文は改行も含めて書かれたとおりに保存し、名前はファイル名になります。名前は資料の一覧で変更できます。
- 資料を持てるのは論文と独立ノートです。専用ノートなど、ほかの項目の持ち物には追加できません（持ち物は1段だけ）。

## 見る

- 右パネルの「メモ」「資料」で切り替えます。資料が複数あるときは「資料を選択」で選びます。
- 「大きく開く」でメイン画面に広げ、「右パネルに戻す」で右パネルに戻します。
- 名前の変更・前へ・後ろへ（資料どうしの順序。メモの順序は変わりません）・削除ができます。削除の前に確認します。
- 左パネルでは、論文・独立ノートを開いたときの持ち物の行に 🌐 付きで並びます。メモ・専用ノート・紐づけ行と合わせて先頭5件まで表示し、残りは「ほか n件」から全件を選べます。クリックすると右パネルで開きます。
- 資料内の CSS と、`data:` で埋め込んだ画像・フォントはそのまま表示します。外部の CDN・Web フォント・画像・スタイルシートは読み込みません。外部に頼る資料は、画像やフォントを CSS・HTML の中に埋め込んだ1ファイルにしてください。

## 資料内のスクリプトを動かす

資料内の JavaScript は、既定では動きません。ボタンや図を動かしたい資料だけ、資料ごとに許可します。

- 資料の上の「この資料のスクリプトを許可」にチェックを入れ、確認で「この資料に許可」を選びます。信頼できる資料にだけ許可してください。
- 許可できるのは、その資料のその内容（本文の SHA-256）に対してだけです。本文が1文字でも変わると許可は無効になり、もう一度許可が必要です。
- 許可はこの PC のこのアプリだけの設定です（画面側のローカル保存。設定ファイルやライブラリには書きません）。Google Drive 同期・バックアップ・別の PC には引き継がれません。資料を削除すると許可も消えます。
- 許可しても、スクリプトに使えるのは HTML 内に書かれたもの（インラインのスクリプト）だけです。外部の `<script src>`、通信（fetch など）、フォーム送信、ページ移動、ポップアップは使えません。アプリの画面・保存データ・API・Tauri のネイティブ機能にも触れません。
- 資料内のリンクや送信で外へ移動しようとすると、枠がエラー表示や空白になることがあります。「再読み込み」で元の資料に戻ります。

## 仕組みと安全性（開発）

資料は信頼できない HTML として扱い、アプリの API や画面と同じ出所では開きません。実装は `sidecar/html_documents.py` と `frontend/src/features/documents/` です。

- 認証側：`POST /api/papers/{id}/documents`（作成。`title`・`content`・`source`）、`GET /api/papers/{id}/documents/{attachment_id}`（説明と `content_hash`）、`POST /api/papers/{id}/documents/{attachment_id}/view`（`content_hash` と `allow_scripts` を渡し、表示用のチケットを返す）。一覧・.html の取り込み・並べ替え・名前変更・削除は、メモと共通の `/api/papers/{id}/attachments` 系を使います。資料の本文を書き換える API はなく、本文を `PATCH` で送ると拒否します。
- チケット：表示の経路 `/html-view/<チケット>` は、起動トークンではなくチケットだけを資格にします。チケットは 256 bit の乱数で、メモリ上にだけ置き、10 分で失効し、同時に256件までです。1つの資料・1つのライブラリ・1つの内容（SHA-256）・1つのスクリプト設定にだけ有効で、資料が変更・削除されたり、別のライブラリが開かれたりすると使えません（変更は `document_changed` で知らせます）。チケットは読み取り専用で、API を呼べません。起動トークンは資料に渡しません。同期・バックアップ・復元でライブラリが使えない間は `library_busy` を返します。
- 配信：資料のバイト列を保存どおりに返し、`Content-Security-Policy` で `sandbox`（許可したときだけ `allow-scripts`）、`default-src 'none'`、`script-src`（許可時のみインライン）、`style-src 'unsafe-inline'`、`img-src data:`、`font-src data:`、`connect-src`・`frame-src`・`worker-src`・`object-src` を `'none'`、`base-uri 'none'`、`form-action 'none'`、`frame-ancestors`（本アプリのウィンドウの出所だけ）を指定します。ほかに `Referrer-Policy: no-referrer`、`Cache-Control: no-store`、`X-Content-Type-Options: nosniff`、カメラ・マイク・位置情報・クリップボードなどを閉じる `Permissions-Policy` を付けます。
- 枠：画面側の `iframe` も `sandbox` を付け（許可時は `allow-scripts` のみ。`allow-same-origin` は付けません）、資料は不透明なオリジンになります。これにより、親の画面・`localStorage`・API・Tauri の IPC を同じ出所として扱えません。
- 親の画面の CSP：本番は `tauri.conf.json` の `frame-src http://127.0.0.1:*` を、起動時に sidecar のポートだけに絞ります（`pin_sidecar_port`、`frontend/src-tauri/src/lib.rs`）。ほかのサーバーは枠に入れられません。`tauri dev`・E2E の Vite 開発サーバーには Tauri の CSP が付かないため、`frontend/vite.config.ts` が `frame-src http://127.0.0.1:8000` を返します。
- 許可の保存：`localStorage` のキー `papeer-html-script:<資料ID>` に内容のハッシュを保存し、表示のたびに現在のハッシュと比べます（`documentPermissions.ts`）。

## 検索・チャットとの関係

資料（HTML）の本文は、横断検索と AI チャットの参照対象です。サマリー・翻訳・AI によるフォルダー整理には使いません。Markdown メモの本文は今のところ対象外です。

- 本文の取り出し：HTML を静的に読むだけで、スクリプトは実行せず、外部も取得せず、資料のファイルも変えません。`<head>`・`<script>`・`<style>`・`<template>`・`<noscript>`・コメントと、`hidden` 属性・`aria-hidden="true"`・インラインの `display:none` / `visibility:hidden` の要素は含めません（外部ファイルや `<style>` の CSS で隠した要素は判別できません）。見出し・段落・リスト・表の区切りは残し、`&amp;` などの文字参照は復号します。上の「スクリプトを許可」の設定とは無関係で、検索・チャットは常に書かれた本文を対象にします。実装は `papeer/core/html_text.py` です。
- キャッシュ：取り出した本文は、資料と内容（SHA-256）ごとにメモリ上へ最大512件・合計1,600万文字まで残します。ファイルの変更・差し替え・削除・復元は次の検索・質問に反映されます。存在しない・読めないファイルは飛ばし、1件の本文は40万文字までです。
- 初回の本文解析では HTML 全体を読み込みます。埋め込み画像の途中で切らず、後ろの本文やスクリプト内の文字列を正しく扱うため、解析中のメモリは原本の大きさに比例します。
- 横断検索：資料の本文に一致すると、持ち主の項目が「資料「名前」」の結果として並びます（ページは付きません）。クリックでその資料を右パネルで開きます。対象は一覧に出る項目（論文・独立ノート）が持つ資料だけで、OCR は要りません。結果は従来どおり200件までで、資料の本文は索引に入れず、検索のたびに読みます。
- チャット：参照範囲（開いている論文・選んだ論文・フォルダー・ライブラリ全体）の項目が持つ資料の本文を、PDF のページと並べて AI に渡します。フォルダーでは、そこに入っているノートの資料も含みます。範囲外の項目の資料は渡しません。小さな範囲では本文全体を、広い範囲や長い資料では質問に合う部分を `max_pages` の枠の中で選び、ページだけで枠を埋めません。
- 出典：資料は `[<持ち主のID>:html:<資料のID>]` の形でページ番号とは別に渡し、回答内では「資料「名前」」のボタンになります。押すとその資料を開きます（PDF の1ページ目へは移りません）。実際に渡した資料だけがボタンになり、渡していない資料や書式の違う引用は「参照未確認」のままです。回答の末尾の参照元にも、渡した資料のリンクを並べます。
- 独立ノート：HTML 資料があれば、OCR をしていなくてもチャットを使えます（サマリーなどは使えないままです）。ページの文字も資料もないノートでは使えません。
- 資料の中の文章は、PDF の本文と同じく根拠として扱い、AI への指示としては扱いません。

## 保存先と同期

資料は `papers/<持ち主のID>/attachments/<資料ID>.html` に保存し、名前・順序・由来（取り込み・自分で作成）はデータベースの `attachments` に記録します。ライブラリのバックアップと Google Drive 同期の対象で、同期の確認画面では資料もメモと同じく項目数で数えます。SQLite スキーマは version 8 のままで、新しい依存はありません。
