# Google Driveのローカルフォルダーで同期

PC版Google Driveが同期するフォルダーをPapeerに指定します。Google Cloudでの登録、OAuthクライアントJSON、Papeer内でのGoogleログインは不要です。

## 最初のPC

1. PC版Google Driveで普段のGoogleアカウントにログインします。
2. Papeerの「設定 → 保存先・同期」を開きます。
3. 「フォルダーを選択」でGoogle Driveのマイドライブなど、PC間で同期されるフォルダーを選びます。選んだ場所の中の `Papeer-sync` が保存先になります。専用フォルダーの絶対パスを直接入力することもできます。
4. 「保存先を設定して同期」を押します。現在のPDF・書き込み・サマリーなどをまとめて保存します。
5. Papeerの処理完了後、**PC版Google Drive側の同期完了も確認**します。

## 別のPC

1. PC版Google Driveに同じアカウントでログインし、同期データが届くまで待ちます。
2. Papeerで、同じ `Papeer-sync` フォルダーのこのPC上のパスを指定します。ドライブ文字やユーザー名はPCごとに異なっていて構いません。
3. 「保存先を設定して同期」を押します。初回は使うデータの選択画面が出るので、元のPCのデータを選びます。
4. 読み込みが終わると画面が再読み込みされます。

Google Driveのミラーリングとストリーミングの違いは[Google公式ヘルプ](https://support.google.com/drive/answer/13401938?hl=ja)を参照してください。ストリーミングを使う場合は同期フォルダーをオフラインでも利用できる設定にすると扱いやすくなります。

## macOS と Linux

macOS のPC版Google Driveは、マイドライブを `~/Library/CloudStorage/GoogleDrive-<アカウント>/` の下に置きます（Finder のサイドバーの「Google Drive」）。「フォルダーを選択」でその中のフォルダーを選んでください。

- 初めて同期するとき、macOS が「“Papeer”が“Google Drive”のファイルにアクセスしようとしています」などと許可を求めます。許可しないと同期フォルダーを読み書きできません。あとから許可するには「システム設定 → プライバシーとセキュリティ → ファイルとフォルダ」を開きます（Papeer のエラーの文にも、この場所を添えます）。Papeer は Apple の開発者登録をしていないため、更新するたびに聞き直されることがあります。
- ストリーミングでは、ほかのPCから届いたファイルは読むときにダウンロードされるため、取り込みに時間がかかることがあります。Papeer の同期フォルダーはミラーリング（またはオフラインで使える設定）にすることをおすすめします。

Linux には Google の公式のクライアントがありません。PC間で同期される**このPCのフォルダー**なら、どの同期ソフトでも使えます（Syncthing、Dropbox の Linux 版、Nextcloud のクライアント、rclone の `bisync` で Google Drive と定期的に同期するフォルダー、Insync など）。Linux の Papeer の文言では、転送するものを「同期ソフト」と書きます。

- ネットワーク上のドライブとして開いたフォルダー（`rclone mount`、GNOME のオンラインアカウントの Google Drive など、FUSE・gvfs のもの）は使わないでください。Papeer は、書き終えたファイルを名前の変更で置き換えることと、ディスクへの書き出し（fsync）で、途中で止まっても壊れた世代を残さないようにしていますが、これらはその動きを保証しません（gvfs の Google Drive では、ファイル名が ID になり、名前の変更も期待どおりに動きません）。
- Windows・macOS のPCと同じ同期フォルダーを使うこともできます。ファイル名は Windows でも使える名前にそろえています。

## 保存対象と動作

PDF、書き込み、付箋・ハイライト、サマリー、翻訳結果・キャッシュ・修正履歴、メモ、チャット、タグ、フォルダー、辞書、テンプレート、設定、カスタムプロンプト、保存済みの読書位置を含むライブラリ全体を保存します。未送信のチャット入力など一時的な入力は対象外です。設定のうちCLIのパスとAPI URLはPCごとに保存し、同期しません。別のPCから届いたデータに書かれていても使いません。

作業用データは引き続きPC内に保持し、選んだフォルダーには、ファイルを中身ごとに1回だけ置き、同期した時点ごとにその一覧（世代）を置きます（後述の「容量と履歴」。以前の形式では、世代ごとにライブラリ全体の `.papeer-sync` ファイルを置いていました）。稼働中のSQLiteデータベースをGoogle Driveから直接開く方式ではありません。フォルダーへの保存とPC間の転送を分け、転送はPC版Google Driveに任せます。PapeerからGoogle Driveのクラウド転送完了は判定できません。

- 自動同期が有効なら、起動後と1分ごとにこのPCと同期フォルダーの変更を確認し、変更があるときだけ同期します。変更の確認ではライブラリを止めず、ファイルも読みません。前回の同期で記録した各ファイルのハッシュ（大きさ・更新日時とともに端末別に `%LOCALAPPDATA%\PapeerSync` に保存）と比べ、変わったファイルがあれば同期に任せます。同期そのものは毎回ファイルから計算し直すので、記録が壊れていても誤った内容を保存したり、競合を見落としたりはしません。大きさ・更新日時を変えずに書き換えられたファイルは確認で気付けないことがあるため、起動後最初の確認では記録を使わず同期します（見落としは次の起動まで。「今すぐ同期」ではすぐ保存されます）。
- このPCの変更は、編集が1分間止まったとき（編集が続く場合は最初の変更から最長5分後）に、待機画面を出さずに裏で保存します。保存中に行った操作は、保存が終わってから実行します（PDF・画像・サマリーの表示はそのまま読み込めます）。他のPCのデータの取り込みは画面を再読み込みするため、待機画面を出して行い（起動後最初の自動同期も、編集を始める前に他のPCの新しいデータを取り込めるよう待機画面を出します）、設定画面や編集中のダイアログ（付箋・訳文の修正・翻訳の設定と辞書・テンプレートなど）を開いている間は待機します。AI処理中は確認も待機します。終了前には、変更が残っていれば保存します。手動で同期するときに編集中のダイアログがあれば、他のPCのデータを取り込むと編集内容が失われるため確認します。
- 同期・バックアップ・復元の前に、書き出し先（同期フォルダー・一時フォルダー・データフォルダーのあるドライブ）の空き容量を確認し、足りなければ書き始める前にエラーにします。
- 「今すぐ同期」でも保存・読み込みできます。別PCに移る前にはGoogle Drive側の同期完了も確認してください。
- 両方のPCに変更があれば、自動上書きせず使うライブラリ全体を選択します。項目ごとの自動結合はありません。選択画面には、同期フォルダーの各最新世代とこのPCのデータの違い（片方にだけある論文の件数と題名、両方にある論文で内容が異なるメモ・付箋・書き込みの件数、論文の数）を表示します。違いは世代の中のデータベースだけを同期フォルダー上でそのまま読んで求めるため、ライブラリ全体はコピーしません（表示用のため世代全体の検証はせず、選んだ世代は取り込む前に従来どおり全体を検証します）。追加と削除の向き（どちらのPCで追加・削除したか）は区別せず、片方にだけあるものとして示します。付箋は各PCが別々に振る番号で突き合わせるため、別々のPCで追加した付箋が同じ番号になると1件として数えることがあり、付箋の件数は目安です（付箋の件数には文章のハイライトも含みます）。
- 選ばなかった側のデータ（他のPCの世代、またはこのPCのデータ）は、このPCの履歴（後述の「このPCの履歴」）に「退避」として自動で残します。種類ごとに最新3件まで残します。論文が1件もないデータや、選んだデータと同じ内容のものは退避しません。他のPCの世代が読み取れないか破損している場合は、その世代だけ退避せずに選択を続け、「保存先・同期」に退避できなかった世代を表示します（同期フォルダーの履歴には残ります）。空き容量不足やこのPCの履歴への書き込みに失敗した場合は、選択を中止します。「設定 → バックアップ」の「このPCの履歴から戻す」から、通常の復元と同じ手順（設定とプロンプトを取り込むかの選択、データの検証、復元後の同期前の確認）で戻せます。
- 他のPCのデータを取り込むとき、取り込み前のライブラリがこのPCの履歴にそろっていて、読み直して確かめられれば、入れ替えで脇へ移したフォルダーは消します（取り込み前の状態は履歴から戻せます）。確かめられないとき（履歴の一部を手で消した、ウイルス対策ソフトが一時的にファイルを開いているなど）は、従来どおり作業フォルダーと同じ階層の `*-before-restore-*` に残し、画面にその場所を表示します。
- 前回の同期と比べて論文・メモ（メモのある論文）・付箋・書き込み（書き込みのあるページ）のいずれかが**5件以上かつ半分以上**減ったとき、または論文が0件になったときは、同期フォルダーへの保存も同期フォルダーからの取り込みも自動では行わず、同期を一時停止します。設定の「保存先・同期」に理由と件数（前回→今回）を表示するので、「このまま同期する」か「同期しない（自動同期を停止）」を選んでください。件数は同期の世代（`revision.json` の `counts`）にも記録します。論文は PDF の論文だけを数え、手書きノート（`notebooks`）と項目が持つ追加のメモ・資料（`attachments`）は別に数えます（メモ・資料を消しただけで「論文が減った」とはなりません。ノートが0件になった場合は論文と同じく確認します）。選択画面と履歴には、ノートや追加のメモ・資料があるときだけその数を示します。古いバージョンが記録した件数にはこの2つがなく、片方に無い種類は比べません。5件未満の削除や、大きなライブラリでの半分未満の整理では止まりません。意図してまとめて削除した場合も、削除したPCでの保存時と、ほかの各PCでの取り込み時にそれぞれ確認が出ます。削除が意図しないものだった場合は、減ったPCでは「同期フォルダーのデータに戻す」、同期フォルダー側が減っていた場合は「このPCのデータを使う」を選ぶと、データを失わずに通常の同期に戻れます。
- バックアップから復元した後の最初の同期も、同期フォルダーに保存する前に同じ画面で確認します（復元したデータが同期フォルダーより古い場合があるため）。復元をやめる場合は「同期フォルダーのデータに戻す」を選びます。
- 同期していたライブラリのデータフォルダーが見つからない場合（移動・削除、外付けドライブの未接続など）は、空のライブラリを作らずにエラーにします。フォルダーを元の場所に戻すとそのまま使えます。新しく始める場合は「保存先・同期」の「新しいライブラリとして始める」を選ぶと、次の同期で同期フォルダーのデータを使うか選べます。
- 両方のPCが同じ内容になっている場合（同じ版に更新したPCがそれぞれデータ形式を移行した場合など）は、競合にせず同期済みとして扱います。
- 保存先が見つからない場合も作業用データはPC内に残ります。エラーや競合の後は定期同期を止めるので、保存先とGoogle Driveを確認して「今すぐ同期」で再試行してください。
- 新しいバージョンのPapeerで作成された世代は取り込まず、Papeerの更新を促します。古いバージョンで作成された世代は、取り込んだ後にこのPCのPapeerの形式へ移行します。同期するPCのPapeerは同じバージョンにそろえてください。
- 「ローカル保存に戻す」はフォルダー同期を停止します。PC内と同期フォルダーのデータは削除しません。
- 保存先のパスや最終同期の基準、CLIのパスとAPI URL、このPCの履歴、papeer-cli が接続先を見つけるための sidecar の起動情報（`instances\`）は、端末別に `%LOCALAPPDATA%\PapeerSync` に保存します（macOS は `~/Library/Application Support/PapeerSync`、Linux は `~/.local/state/papeer`。README「データの保存場所」）。

## 容量と履歴

同期フォルダーの `v2\` に、ライブラリのファイルを中身ごとに1回だけ置きます（中身の SHA-256 が名前。PDFと画像はそのまま、それ以外は圧縮）。データベースは 256 KB ずつに分けて置くため、メモを1つ直しただけなら、同期フォルダーに増えるのは変わった部分と、どのファイルでできているかを書いた小さな世代ファイル（`gens\`）だけです。論文を1本足したときは、その論文のファイルの分だけ増えます。変更がないときは新しい世代を作りません。読書位置だけの変更は新しい世代を作るきっかけにはせず、次に内容を同期するときに含めます。

同期フォルダーに残すのは、最新の世代と、ほかのPCがまだ使っている世代（各PCが最後に同期した世代。30日以上同期していないPCの分は残しません）だけです。使われなくなった世代とファイルは、同期が済んだときに片付けます（ファイルは、どの世代も使わなくなってから3日後。1日1回、1回に2 GBまで）。Google Driveでは消したファイルがごみ箱に移り、30日たつか、ごみ箱を空にするまで容量に数えられます。以前の状態は、同期フォルダーではなく、このPCの履歴（次の節）に残します。同期フォルダーの中のファイルを手で消さないでください。

- 各PCの同期の記録（`devices\`）には、PC名と最後に同期した世代を書きます。
- Google Driveはファイルを順不同に届けます。世代ファイルが先に届き、使うファイルがまだ届いていないときは、取り込まずに「同期データの到着を待っています」と表示し、届いた時点で自動で同期します（待っている間、このPCの変更は同期フォルダーに保存しません。このPCには保存されています）。24時間以上届かないときは通知します。待たずに進めるときは「保存先・同期」の「このPCのデータで続ける」を選びます（届いていない世代は、届いた後に選択画面に出ます）。
- 同期フォルダーのファイルが壊れていたときは取り込まず、そのファイルを書いたPCが次の同期で書き直します。

### 新しい同期の形式への移行

以前の形式の同期フォルダー（`.papeer-sync` のZIPが並ぶもの）では、「設定 → 保存先・同期」に「新しい同期の形式に移せます」と表示します。「移す」を押すと、まず今までの形式で同期し、次にライブラリを新しい形式で保存して、以前の形式の側には「移った」ことを示す小さな印の世代を置きます。初回はライブラリ全体を書くため、Google Driveへの転送に数分〜数十分かかります。「あとで」を押すと、次に起動するまで表示を小さくします。

- 競合・確認・到着待ちで止まったときは、その画面が出ます。解決する同期がそのまま移行を続けます。
- 途中で止まったとき（アプリの終了、エラー、別のPCが同時に同期した）は「移行の途中です（次の同期で続けます）」と表示し、次の同期で続けます。同期フォルダーにすでに書いたファイルは書き直しません。
- 待機画面の「中止」を押すと、移行もやめます（以前の形式のまま同期を続けます）。もう一度「移す」で始められます。
- 新しい版のPapeerを入れたほかのPCは、次の同期で自動で新しい形式に切り替わります。変更がなければ、ファイルはほとんど手元にあるため、取り込むのは変わった分だけです。
- 空のフォルダーを同期フォルダーに選んだときは、確認なしで新しい形式で始めます。

### 古い版のPapeerと混ざったとき

新しい形式に移った同期フォルダーでは、古い版のPapeerは印の世代で止まり、「この同期データは新しいバージョンのPapeer（x.y.z）で作成されたため取り込めません。このPCのPapeerを最新版に更新してから同期してください。」と表示します。ライブラリは変わりません。そのPCのPapeerを更新してから同期してください。

古い版のPapeerで変更があったPCが、競合の画面で「このPCのデータを使う」を選ぶと、以前の形式で保存されます。新しい版はそれを見つけると、選択画面に「（古いバージョンのPapeerで保存）」として出します。使うことも、使わずに履歴へ退避することもできます（どちらでもデータは失われません）。移行の途中に新しい版が以前の形式で保存した変更は「（同期の形式を移す途中に保存）」と出します。

### 古い形式の同期データの片付け

移行しても、以前の形式のZIPは自動では消しません。「保存先・同期」に「古い形式の同期データ：23個・18.4 GB」のように表示し、すべてのPCが新しい形式で同期すると知らせます。「削除する…」はいつでも押せます。確認の文には、消す数と大きさ、ごみ箱の30日のこと、残すもの、まだ新しい形式で同期していないPCの名前を書きます。

- 選択画面にまだ出ている古い版の世代は消しません。印の世代は1つ残します（古い版のPapeerを止めるため）。
- 片付けた後、古い版のPapeerのPCは、更新するまで同期できなくなります（一度同期したことのあるPCは「前回の同期データが見つかりません」と表示します。ライブラリは変わりません）。ほかにもPCがあれば、先にPapeerを更新して同期してください。30日以内に以前の形式で**保存した**PCだけを名前で示すため、取り込むだけだったPCは示されません。

### このPCの履歴

同期で保存・取り込みしたときのライブラリの状態、競合で選ばなかった側、復元の直前の状態を、このPCの `%LOCALAPPDATA%\PapeerSync\history\` に残します（同期・バックアップの対象外）。同じ内容のファイルは1回だけ保存し（中身の SHA-256 で区別します。PDFと画像はそのまま、それ以外は圧縮）、データベースは 256 KB ずつに分けて変わった部分だけを足すため、使う容量はライブラリ1つ分と変更分です。試験用の合成ライブラリ（192 MB）では、1日10回の同期を5日続けても 174 MB（ライブラリの約0.9倍）で頭打ちでした。

- 残す記録：直近の同期 N 件（既定 5）と、Papeerで同期した日ごとのその日の最後の記録を D 日分（既定 3。使わなかった日は数えません）。選ばなかった側と「戻す前」は、それぞれ最新3件です。ただし、ほかに残る記録と同じ状態の「戻す前」は数えずに残し、過去の時点に戻してから何も変えずに別の時点へ戻したときの「戻す前」（過去の状態に今の設定を合わせたもの）は、別に最新3件を残します。そのため、いくつかの時点を試しても、最初に戻す前の状態は押し出されません。N と D は「設定 → バックアップ」でPCごとに変えられ、減らすと削除される記録を確認してから保存します。余った記録は次の同期（または復元）の後に消します。
- 「設定 → バックアップ」の「このPCの履歴から戻す」で、各時点の今との違いを見てから、その時点に戻せます。戻す前のライブラリも「戻す前」として履歴に残します（履歴に同じ状態がすでにあり、読み直して確かめられれば、新しくは作りません）。バックアップのZIPから復元するときも同じです。データベースが壊れているなどで戻す前のライブラリを記録できないときは、記録せずに復元を続け、元のライブラリを作業フォルダーと同じ階層の `*-before-restore-*` に残します。
- 各記録は、ファイルをすべて書き終えてから最後に一覧を書くため、途中で止まっても中途半端な記録は残りません。使われなくなったファイルは次の片付けで消します。取り込み前のフォルダーを消す前や、履歴から戻す前には、記録のファイルをすべて読み直して確かめます。破損していたファイルは `damaged\` に移し（7日後に削除）、次に同じ内容を記録したときに書き直します。
- 以前のバージョンがライブラリの隣に残した `*-sync-backups` のZIPと `*-before-restore-*` のフォルダーは自動では消しません。「設定 → バックアップ」の「以前のデータ」に大きさとともに一覧し、選んで確認してから削除できます。データフォルダーの場所を変える前などの別の場所のライブラリの履歴も、同じ画面の「別の場所のライブラリの履歴」から削除できます。

自動テストでは2つのローカルフォルダー間の転送（順不同の到着を含む）、競合、破損、転送途中、保存先の消失、移行の途中での停止、古い版との混在を検証しています。実際のGoogle Drive経由の転送は各PCの設定に依存します。
